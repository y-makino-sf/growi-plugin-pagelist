
# GROWI「配下ページ一覧＆ポータル表示」プラグイン (growi-plugin-pagelist) 仕様書

## 1. 記法とオプション仕様

Markdown本文内で `$pagelist(...)` を記述することで、用途に応じた一覧を描画する。

| オプション | 指定可能な値 | デフォルト値 | 説明 |
| :--- | :--- | :--- | :--- |
| **対象パス**（第1引数 / `path`） | パス文字列（例: `/TechKnowhow`） | 現在のページパス | 探索起点となる親ページパス。起点ページ自身は一覧から自動除外される。 |
| **`limit`** (別名: **`num`**) | 数値（例: `5`, `10`） | `10` | 1ページあたりの表示件数。 |
| **`recursive`** | `true` / `false` | `true` | `true`: サブフォルダ以下全階層を再帰探索。<br>`false`: 直下の1階層のみ探索。 |
| **`sort`** | `updatedAt` (更新日時順)<br>`createdAt` (作成日時順)<br>`popular` (人気総合スコア順)<br>`views` (閲覧者数順)<br>`likes` (いいね数順) | `updatedAt` | 並び順の指定。`popular` は `(いいね数 × 2) + 閲覧者数` で算出する。`popular` / `views` / `likes` 指定時はランキング王冠バッジと閲覧数・いいね数を強調表示する。 |
| **`tag`** | タグ名（例: `pickup`, `必読`） | `""` (指定なし) | 指定時は `GET /_api/search?q=tag:<tag>` を呼び出し、該当タグが付いたページを抽出する（対象パスも指定されている場合はそのパス配下で絞り込む）。 |
| **`view`** | `list` (リスト表示)<br>`card` (カードグリッド表示) | `list` | `list`: コンパクトな1列リスト。<br>`card`: Bootstrapカードを用いた2列グリッド表示（おすすめ枠・人気枠向け）。 |
| **`newdays`** | 数値（例: `3`, `7`, `0`） | `3` | 指定日数以内に更新されたページに `NEW` バッジを表示する（`0` で非表示）。 |
| **`excerpt`** | `true` / `false` | `true` | カード・リスト共通の本文抜粋。`false` は他の抜粋指定より優先し、追加API通信も省略する。 |
| **`excerptlength`** | 正の整数（1〜350） | `200` | 装飾除去・空白整形後の最大文字数。省略記号も文字数に含める。 |
| **`excerptlines`** | 正の整数（1〜10） | `3` | 最大表示行数。文字数制限を適用した後、CSSで行数制限する。 |

数値は空・0・負数・小数・非数値の場合に既定値へ戻し、上限超過の正の整数は上限へ丸める。`excerpt` は前後空白・大文字小文字を正規化し、`true` / `false` 以外は既定値とする。

## 2. API呼び出しとデータ整形の内部設計
1. **通常取得（`tag` 未指定時）**:
   - `GET /_api/v3/pages/list?path=...&limit=...&page=...` を呼び出す。
   - ただし、`sort` が `popular` / `views` / `likes` の場合や `recursive=false` の場合は、クライアント側で全件ソート・階層フィルタを行うため `limit=100, page=1` で母集団を取得し、クライアント側でソートおよびページネーション（スライス）を行う。
2. **タグ検索取得（`tag` 指定時）**:
   - `GET /_api/search?q=tag:<tag>` を呼び出す。レスポンスの `data` 配列（または `pages` 配列）からページ情報を抽出し、指定パス配下のフィルタおよびソート・ページングを適用する。

3. **本文抜粋の追加取得**:
   - 一覧・検索の続きも取得してソート・階層フィルタ・自ページ除外・ページ分割した後、表示中IDだけを対象とする。
   - `GET /_api/v3/page-listing/info?attachShortBody=true&pageIds[]=ID...` を呼び出す。1件の場合も配列とし、50IDずつ直列で取得する。
   - 応答の `data` はページIDをキーとする情報マップ。その `revisionShortBody` を本文として使用する。空文字は空本文、欠落やnullは本文情報なしとして区別する。
   - GROWI 7.1.9の標準APIは元Markdownの冒頭350文字を返すため、テキスト化後の文字数は350文字未満になり得る。全文APIへの自動切替はしない。
   - 文字列として得られた本文のみ、コンポーネント内でID・更新日時の組に紐付けて保持する。本文欠落・失敗は成功キャッシュにしない。一覧再取得時はキャッシュを無効化する。
   - `excerpt=false` の場合は追加取得をスキップ。途中でオフ・ページ変更・アンマウントになった場合は中止し、古い応答を表示にもキャッシュにも反映しない。
   - 一部チャンクの失敗時も成功した抜粋を維持し、再試行で未取得分を補う。タイトル・リンク等の一覧は常に残す。

## 3. 標準ページ一覧に近い表示

- カード・リスト共通で、親パス、更新者アバター、最終パスセグメントのタイトル、足跡（`seenUsers.length`）、抜粋、補足メタデータを表示する。
- アバターの画像なし・読込失敗時は更新者の頭文字を表示する。足跡はPVではなく閲覧者数。
- Markdownは構文木から表示テキストを取得する。HTMLノードは除外し、Reactの通常テキストとして描画する。リンクは表示文字、画像は代替文字、コードは内容を残す。
- プレーンテキスト化、空白整理、Unicodeコードポイント単位での文字数制限、行数制限の順で適用する。絵文字のサロゲートペアを分割しない。
- 短い本文には固定高さを設けず、抜粋オフ・空本文・本文欠落時は抜粋領域を省略する。
- GROWI内部のReactコンポーネントは直接利用せず、既存のReact共有ファクトリとView/Preview二重フックを維持する。
